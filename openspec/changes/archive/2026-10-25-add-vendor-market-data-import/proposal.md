# Proposal: 第三方长历史行情接入（每供应商独立源 + 数值化质量契约）

## 1. 背景与核心痛点

系统当前分钟级历史完全依赖 QMT，实测边界（2026-10-24 生产库核查）：

- 5m 只有 **2025-07-03 起**（约 1.3 年，每指数 1.4~1.5 万根），首日仅下午 24 根；
- 30m 更窄：只有 `000001`（2,476 根）与 `399006`（2,300 根）有 QMT 原生 30m；`000300`/`399001` 只有 TDX 2026-05~08 短窗口，`399673` 没有；
- 缠论多级别联立（5m/30m/日线）与大级别结构验证需要 10~20 年分钟级数据，现状无法支撑。

已采购第三方 5m 数据（5 个指数，2005~2026，合计 **971,849 根**），实测结论：

| 核查项 | 实测结果 |
|---|---|
| 时间戳口径 | **bar 右端**（09:35/15:00），与生产库 QMT 5m/30m 一致 → **不减 5 分钟** |
| 与 QMT 5m 重叠 | 每指数 1.38~1.50 万根，`|Δclose|` p99 = 0.0056，最大 0.0060；仅 2026-03-23 09:40 深市三指数各 1 根被截断 |
| 与 QMT 日线 | 按日聚合收盘 **100% 落在 0.1% 内（中位 0.0000%）**，日高/日低 p99 ≤0.03% |
| 交易日完整性 | vendor 区间内**一天不缺** |
| 30m 派生 | session 每 6 根分块，对 000001 QMT 30m 的 2,436 根重叠：close max 0.0059、high max 0.0256 |
| 价格质量 | 000300 有 4 个 2005-2006 坏日，**仅日内 H/L 失真，O/C 与官方一致** |
| 量额口径 | 000001 2011-07-27 前混入基金量；399001 成分股口径（≈0.31×QMT）；399006 2017 断点；399673 2014 量额整体错乱 |
| 库内前置 | 5 个指数在 `securities` 均为 `INDEX`（id 5/6/7/8/13），**无 000001 与平安银行冲突** |

三项代码层阻塞：

1. `k.source` 枚举只有 `ef/tdx/qmt`，无法登记第三方数据；
2. `k` 没有可参与计算的质量表达——现有的 `ok/repaired/bad`、`constituent` 这类标签只能看，不能算；
3. 回测运行时白名单只接受 `tdx|qmt`。

## 2. 目标与范围

### 2.1 核心目标

1. **每个第三方供应商一个独立 source**：`vendor_a`、`vendor_b` ……（用户决策 B）。
   - 不同供应商的数据天然按 `source` 隔离，可在同一 bar 上并存，唯一键不冲突；
   - 新增供应商 = 1 个枚举值 + 1 条 migration，读路径无需改动。
2. **质量用数值表达，可直接参与运算**：
   - 每个字段一个 `0/1` 可用掩码（open/high/low/close/volume/amount）；
   - 量额另带 `scale`（量纲归一因子）与 `caliber_epoch`（口径分段号）；
   - 例：`SUM(volume * volume_valid * volume_scale)`、`WHERE high_valid=1 AND low_valid=1`。
3. **5 分钟原生入库 + 30 分钟按 session 派生**（熔断日保留真实截断）。
4. **回测消费 `vendor_*`**：单源回放，不做跨源合并。
5. **本地 dev 数据层按显式优先级拼接并缓存解析结果**。
6. **可校验、可回滚**：导入前预检 + 导入后 SQL 对账 + 按 source 删除回滚。

### 2.2 非目标

- 不做回测运行时的跨源合并（既有 `backtest-runtime` 契约明确禁止）；
- 不做 vendor 采集器、增量同步、定时任务；
- 不改 QMT/TDX 既有行；
- V1 不把质量掩码透传进 `StrategyBar` / 因子内核（数据层可算即可，透传另立项）；
- 不做 1m/60m 与 000688 科创50。

## 3. 影响面

| 仓库 | 影响 |
|---|---|
| `mist` | 迁移 030、`DataSource.VENDOR_A`、`KQuality` 实体、回测 allowlist、导入工具、dev 拼接与缓存 |
| `mist-fe` | `DataSourceValue` 联合类型 + 回测/看盘下拉新增 vendor_a |
| `mist-deploy` | 无新 service；迁移 030 本次单独 apply（不连带 027~029） |
| 数据库 | `k.source` 追加 `vendor_a`；新建 `k_quality`；导入 1,133,828 行 + 同量质量行 |

## 4. 风险

| 风险 | 处置 |
|---|---|
| 生产 enum DDL | 收盘后执行；只追加值；先记录 `SHOW CREATE TABLE k` |
| 027~029 未应用 | 只手工应用 030，不替在途 change 提前改表 |
| 113 万行 + 113 万质量行 | staging + `LOAD DATA`；F: 余量 169G |
| 质量掩码判错 | 掩码规则逐条写进 spec，导入前输出分布报告供人工复核 |
| 4 个坏日 | 全量入库，`high_valid=low_valid=0`，不剔除以免造日期缺口 |
| 本地大 JSON | provider 加 mtime 缓存 |
