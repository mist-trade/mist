# Proposal: 引入独立的战术事件汇聚层（Tactical Event Layer）

## Why

在 2026-10-28 针对 2005~2026 年（4.1 万根 30m / 24.8 万根 5m / 7400 根日线）全量历史数据的 9 组评测中，暴露出三大核心架构痛点：

1. **信号与状态混淆，漏斗损耗超 95%**：
   宏观体制（`plugin.regime`）、均线排列等状态类插件在牛市/空头期间**逐 Bar 持续喷出 `action: BUY`**，导致 21 年回测中产生了高达 22,018 条原始信号。而交易层单标的持仓状态机（`PositionStateMachine`）在持仓期间将后续买单全部忽略，导致 **98.1% 的信号被静默吃掉**，持仓状态成了事实上的隐式去重器，使得入场时机被上一次出场的偶然性所扭曲。
2. **多因子同 Bar 硬绑（AND 门禁）失真，复合策略夏普暴跌**：
   不同维度的因子具有天然的物理因果与相位差：宏观体制是长周期背景（Setup），缠论买卖点是波段端点扳机（Trigger），而量价（VPCI）/动量（挤压）是微观放量确认（Confirmation）。若在同一根 30m Bar 上强行执行硬 AND 门禁，只能筛选出极端追涨杀跌的畸形形态，导致复合树（`07_composite_stress`）平均持仓被碎割至仅 2.8 天，夏普比率跌至 -0.6152。
3. **消费者直连原始信号引发的次生灾害**：
   - **实盘告警端**：实盘目前维持轻量告警（`apps/signal` 直连 `apps/notification`，暂不引入模拟仓记账）。若信号侧狂喷状态，由于去重主键带 `signalTime`，每根 Bar 都会触发一次企微/飞书推送，秒级触发机器人限流熔断（企微 20条/分，飞书 100条/分）并产生死信；
   - **前端图表端**：图表渲染层直接读取 `KernelSignal` 绘制 Markers。成千上万个连续标记导致 K 线图表被完全遮蔽，产生严重的视觉污染与 Canvas 掉帧。

## What Changes

针对上述问题，我们彻底摒弃“在纯算力插件内私自加抑制补丁”或“将研判逻辑堆砌到交易撮合层”的妥协做法，在**信号层**与**交易/消费层**之间正式引入一个独立的**【战术事件汇聚层】（Tactical Event Layer）**：

```
┌────────────────────────────────────────────────────────────────────────┐
│               【第 1 层：纯净信号层 (Raw Signal Layer)】                  │
│   • 承载：StrategyEvaluationKernel + 纯数学因子插件 + 决策树节点          │
│   • 原则：100% 保持纯净、无隐式抑制、逐 Bar 原始发射状态与观测            │
│   • 价值：完全透明、无未来函数、保留原始因果证据，专供算法调优与白盒排查 │
└───────────────────────────────────┬────────────────────────────────────┘
                                    │ 原始信号流 (Raw KernelSignal[])
                                    ▼
┌────────────────────────────────────────────────────────────────────────┐
│            【第 2 层：战术事件汇聚层 (Tactical Event Layer - NEW)】       │
│   • 承载：TacticalEventAggregator（边沿化 + 时序因果观察窗 + 去抖冷却） │
│   • 核心能力：                                                         │
│     1. 边沿跃迁检测 (Edge Detection)：State(t) != State(t-1) 才生成事件 │
│     2. 因果时序观察窗 (Temporal Window Consensus)：t ~ t+W 内等待微观确认│
│     3. 战术冷却与去抖 (Tactical Cooldown)：防震荡高频抽打               │
│   • 产出：高信噪比、离散化的 TacticalEvent（战术买卖事件）             │
└───────────────────────────────────┬────────────────────────────────────┘
                                    │ 战术事件流 (TacticalEvent[])
                                    ▼
┌────────────────────────────────────────────────────────────────────────┐
│             【第 3 层：消费与呈现层 (Consumers & Dual-View UI)】         │
│   • 实盘告警 (apps/notification)：只消费 TacticalEvent，杜绝告警风暴   │
│   • 回测交易 (SimulatedBroker)：只消费 TacticalEvent，合理波段持仓     │
│   • 前端双层可视化 (Dual-View)：支持自由勾选切换：                    │
│     - [ ] 原始信号层（调试排查透视）                                   │
│     - [x] 战术事件层（战术买卖点）                                     │
│     - [x] 撮合成交层（实际成交与持仓区间）                             │
└────────────────────────────────────────────────────────────────────────┘
```

## 业务价值与工程收益

1. **信号层纯净无染**：
   `StrategyEvaluationKernel` 与各类因子插件完全不需要掺杂任何业务级抑制逻辑，保持无副作用的确定性数学推演，排查问题时直视最底层的市场状态。
2. **告警与交易彻底安全**：
   告警推送和交易撮合只对接到战术事件层，22,000 条状态杂音被收敛至几十到上百个真正确立的买卖机会，消灭通知风暴与回测过度交易磨损。
3. **前端多重视角并存**：
   图表既能展示清晰稀缺的战术买卖点，又能随时一键开启“原始信号透视”，彻底解决“想要排查算法细节却又嫌图表杂乱”的两难矛盾。
